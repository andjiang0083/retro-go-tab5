# tab5p —— retro-go Tab5 **竖屏**版本（独立版本线，从 0.0.1 起）

> 本目录是**独立 target**，与横屏主线 `targets/tab5/` **互不干扰**。
> `rg_tool.py` 自动扫描 `targets/*/config.h` 注册 target → 本目录存在即自动生效，
> **无需修改任何共享文件**。

## 为什么做竖屏

面板**原生就是 720×1280 竖屏**，而横屏版把逻辑画面做成 1280×720、在驱动里做 **90° 映射**
（= 逐行转置）。代价：内存**跳着读**（每 1440 字节只碰 64 字节），实测仅 28MB/s，
而顺序读可达 89MB/s → 这是 `transpose=` 那段 **6~8ms/帧** 的来源，也是显示通路里最贵的一项。

**竖屏下逻辑画面 = 720×1280 = 物理布局 → 映射退化为恒等 → 读写全部顺序化** ✓
预期 `transpose=` 掉到 ~1ms，足以让总开销跨进 60fps 的 16.7ms 预算。

## 关键事实（已核实，别搞错）

- 核心输出 **240×160**，缩放 **3× 整数 = 720×480**
  → **竖屏下游戏画面尺寸与横屏完全相同（720×480）**，只是位置从"居中两侧留白"变成"顶部"
  → 不存在"画面变小"的代价 ✓
- 竖屏布局：`y=0..480` 游戏画面（满宽 720）· `y=480..1280` 控制区（**800px 高**，
  对比横屏两侧各 280px 宽 → 触摸区域大幅改善 ✓）
- 面板与 BSP **本来就是竖屏配置**，**不需要动面板、不需要动 BSP** ✓

## 文件隔离规则（必须遵守）

| 内容 | 竖屏版本用 | 横屏主线（不动） |
|---|---|---|
| target 目录 | `targets/tab5p/` | `targets/tab5/` |
| 显示驱动 | 本 target 自己的驱动文件 + 新驱动编号 | `mipi_dsi_tab5.h`（编号 2） |
| 触摸布局 | `targets/tab5p/touch_layout.h` | `targets/tab5/touch_layout.h` |
| 构建 | `python3 rg_tool.py --target tab5p ...` | `--target tab5` |
| 产物镜像 | `retro-go_v0.0.1_tab5p.img` | `retro-go_v0.7-*_tab5.img` |
| 文档 | `docs/PORTRAIT-*.md` | `docs/NIGHT-*.md` |
| M5Burner | 独立条目（另行起名，从 0.0.1） | `retro-go Tab5`（0.3） |

**原则：竖屏的任何改动都不得修改横屏 target 引用的文件。** 共享代码若必须改，
先评估对横屏的影响并单独验证。
