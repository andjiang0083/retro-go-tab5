# Code of Conduct

Short version: **be decent, assume competence, and argue about the code rather than the person.**

Concretely, in this project's spaces (issues, PRs, discussions):

1. **Criticism is welcome; contempt is not.** "This approach will wedge the panel because X" is good. "This is obviously wrong" is not.
2. **No harassment, discrimination, or personal attacks.** Age, body, disability, ethnicity, gender identity or expression,
   experience level, nationality, personal appearance, race, religion, or sexual identity are not up for debate here.
3. **Respect that people work on this for free.** A slow review is not an insult, and a rejected patch is not a verdict on you.
4. **Hardware claims need evidence.** "It is smoother" is fine, but if you are asserting a number, say how you measured it.
   Being wrong with data is useful; being confident without it wastes everyone's time.

Maintainers may edit, lock, or delete anything that violates this, and will explain why. Repeated violations lead to being blocked
from the repository.

To report a problem, open a private report via the repository's Security tab or contact a maintainer directly. Reports are handled
confidentially.

*This is a deliberately short code of conduct — proportionate to a small hardware project. It applies to everyone equally, including maintainers.*
