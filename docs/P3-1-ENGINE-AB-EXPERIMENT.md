# P3-1 · 「动态翻译 vs 解释器」受控实验（issue #4）

> 真机：M5Stack Tab5（ESP32-P4），2026-10-08 夜间无人值守跑，固件为**静音诊断构建**
> （`RG_TEST_MUTE`：音量写死 0 并落盘，避免长时间自动跑吵到人；`RG_TEST_NO_AUTOSAVE`：禁 SD 自动写）。

## 一、问题与假设

issue #4 的线索是「同一套核心在宿主与真机行为不一致 / 取名界面方向键错乱」，
其中一个待验证假设是：**P4 移植版的动态翻译（dynarec）与解释器行为不等价**。

`gbsp/main/main.c` 里已有现成开关 `dynarec_enable`（1 = 动态翻译，0 = 解释器），
所以无需改逻辑即可做 A/B：**同一台设备、同一 ROM（恶魔城_晓月之圆舞曲）、同一编译进固件的按键时间轴**，
只切这一个值，各抓 180 秒，比对 `DIAG_ST f=<帧> rh=<寄存器哈希> pc=<PC> mh=<内存哈希>` 序列。

两个镜像 md5 不同（`007878a0…` vs `5a734732…`），证明 A/B 确实落在不同二进制上。

## 二、结果（第一次跑：看起来像"引擎分岔"）

```
前 144 帧（含 BIOS 启动段）两引擎 rh/pc 逐帧一致
第 145 帧（≈2.4 秒）首次分岔：
   f=144  dynarec rh=BE3DDD3C pc=000004A0   interp rh=BE3DDD3C pc=000004A0
   f=145  dynarec rh=66270CD0 pc=08000D5E   interp rh=BE3DDD3C pc=000004A0  ← 分岔
共同 576 帧里仅 50 帧一致（持续性分岔）
但两者最终停在**完全相同**的状态：pc=000004A0、rh=BE3DDD3C 恒定，而 mh 持续变化
  ⇒ 都在跑，CPU 处于 BIOS 空转/等待态（等中断或等输入）
```

如果就此收尾，结论会是「两引擎不等价 ⇒ 至少一方周期/中断会计有问题」。**先做控制实验再下结论。**

## 三、控制实验（决定性的那一步）

**同一颗 dynarec 固件，连续刷两遍、各抓 120 秒，再比对：**

```
run1 517 条 / run2 516 条，共同帧 516 个（f 1..6180）
✗ 第一处分岔同样在 f=145（形态完全一致，只是这次换另一遍跑进了 ROM）：
   f=145  run1 rh=BE3DDD3C pc=000004A0   run2 rh=66270CD0 pc=08000D5E
   之后同样长期不收敛
```

## 四、结论

1. **同一颗固件自己跟自己都对不上**（同样的 f=145、同样的分岔形态）⇒ 这套比对**测不出引擎差异**，
   它测到的是**逐次启动之间的非确定性**。第一次跑出来的"引擎分岔"是**假发现**，不能作为证据。
2. 因此本实验**未能**支持"两引擎行为不等价"的假设，也**未能**否定它——**只是证伪了方法本身**：
   在这台设备上，「按主机帧号取 CPU 状态」不是有效的确定性时钟。
3. 顺带确定的事实：那个 `pc=000004A0 / rh 恒定 / mh 变化` 的空转等待态，**在解释器和动态翻译下都会出现**，
   与引擎无关（是这一段 ROM 在该输入下的稳定行为）。
4. **这不是白跑**：它给出了 issue #4 的下一步方向——先把仿真变成**逐次可复现**，再谈引擎对比。
   候选不确定性来源（按可能性排序，均未验证）：
   - 帧循环的**仿真周期预算依赖宿主墙钟**（跑多跑少由实时节奏决定）⇒ 同样的"第 N 帧"对应不同仿真进度；
   - 核心从**宿主 RTC/墙钟**取种子（GBA RTC 类卡带模拟常见做法）；
   - 启动路径里有**未初始化/竞态**状态。

## 五、对既有结论的影响

- **P2-1 / P2-2 的数字不受影响**：它们比的是**速率**（每秒推屏行数、显示通路 ms/s），不是"第 N 帧的状态"，
  与逐次确定性无关。
- **P2-5 / P2-4 / P1 系列不受影响**。

## 六、下一步（建议，尚未执行）

1. 让帧循环的仿真周期预算**固定**（或改为按累计周期驱动），并去掉宿主墙钟/种子的影响；
2. 复跑本文件第二节的 A/B —— 若控制实验（同固件两遍）变成零分岔，则这次的引擎比对才有意义；
3. 只有在确定性成立后，才把差异归因到 dynarec/解释器，并据此定位 issue #4 的方向键错乱。
